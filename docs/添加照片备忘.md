# 添加照片备忘

## 日常流程

```bash
# 1. 拷进去（-p 保留拍摄时间戳，照片按此倒序排列）
cp -p ~/Pictures/新照片/*.jpg public/static/images/gallery/planes/

# 2. 提交。压缩由 pre-commit 钩子自动完成
git add public/static/images/gallery
git commit -m "add: 新增台北拍机照片"
```

**只有这两步。** 压缩（缩到 2560px、剥 EXIF、体积降 95% 以上）由 git 钩子在提交时
自动做；照片清单 `app/gallery-data.json` 由 `predev` / `prebuild` 自动重新生成，
Vercel 部署时也是自动的。

如果新照片里有**没拍过的航司**，多做两步（见下方「遇到新航司」）。

---

## 文件命名

```
航司_机型_机场_注册号[_彩绘].JPG
```

```
UA_B757-200_IAD_N41135.jpg              ← 四段
BR_B777-300ER_TPE_B-16715_SA.JPG        ← 五段，最后是彩绘
```

| 段 | 写什么 | 说明 |
|---|---|---|
| 航司 | **IATA 二字码** | `UA`、`BR`、`3U`。页面上会自动显示成全称 |
| 机型 | 自由书写 | `B777-300ER`、`A330-900neo` |
| 机场 | IATA 三字码 | `TPE`、`NRT`、`IAD` |
| 注册号 | 自由书写 | `B-16715` |
| 彩绘 | 自由书写，**可省略** | `SA`、`Star Alliance` |

- 分隔符是**下划线**，段内可以有空格和连字符
- 大小写扩展名都行（`.jpg` / `.JPG`）
- 前四段建议都写；少写了对应字段留空，不会报错
- **同一架飞机拍到第二张**：文件名必须唯一，在最后加一个数字段区分——

  ```
  NH_B767-300_HND_JA614A_SA.jpg      ← 第一张
  NH_B767-300_HND_JA614A_SA_2.jpg    ← 第二张
  ```

  结尾的纯数字段只用来区分文件，不参与解析，两张照片的字段完全一样
- 彩绘段跟着已有的写法走：星盟涂装 `SA`、寰宇 `OW`、天合 `ST`，其余写名字
  （`Disney`、`pokemon`）。同一种涂装写法不一致的话，筛选栏里会多出一个重复项

哪些字段能筛选由 `public/static/images/gallery/planes/schema.json` 决定。
注册号只展示不筛选（每张都不同，做成筛选项会把侧边栏撑爆）。

相册筛选栏的两个行为在 `components/gallery/GalleryGrid.tsx` 顶部改：
`GROUP_ORDER` 是分组从上到下的顺序，`DROPDOWN_THRESHOLD` 是选项超过多少个就
收成下拉框（默认 10，所以航司、机型是下拉，彩绘、机场平铺）。

## 遇到新航司

拍到一家没拍过的航司时，多做两步：

### 1. 在 `data/airlines.json` 里补一条

```json
"BR": { "name": "EVA Air", "alliance": "star", "domain": "evaair.com" }
```

- `alliance`：`"star"` / `"skyteam"` / `"oneworld"`，确认不属于任何联盟就写 `null`
- `domain`：官网域名，用来抓图标。没有独立官网的写 `null`（如上航已并入东航，
  填 `ceair.com` 只会抓到东航的图标，是错的），脚本会干净地跳过

**不补也不会出错**——这家航司会出现在机库页面末尾的「未分类」组里，标粉色提醒你。
`npm run generate-gallery` 也会在命令行直接打印警告。这是有意设计的：静默归类会让
错误藏起来。

### 2. 抓图标

```bash
npm run fetch-airline-icons
```

只抓已经拍到、且还没有图标的航司。没有图标的航司会显示首字母彩色方块，不影响使用。

## 遇到新机场

和新航司同一套约定，在 `data/airports.json` 里补一条：

```json
"HND": { "name": "东京羽田机场", "en": "Tokyo Haneda", "city": "东京", "region": "asia" }
```

`region` 取 `regions` 里的 id：`asia` / `europe` / `north-america` / `south-america` /
`oceania` / `africa`，只分到大洲。不补的话机场会进机库页面的「未分类」组。

## 备忘：几条容易忘的

- **`cp -p`** 的 `-p`：照片按文件修改时间倒序排列。不加 `-p` 的话一批照片时间戳
  全变成当下，顺序会乱
- **改文件名 = 改 URL**。航司详情页地址是 `/airlines/<小写代码>`，分享出去的链接
  会因重命名失效
- **不要在 `npm run dev` 开着的时候跑 `npm run build`**。两者共用 `.next` 但产物
  结构不同，会让页面报 `missing required error components`。要验证生产构建用：

  ```bash
  npm run build:check    # 输出到 .next-check，可与 dev 并行
  ```

- **改了 `data/airlines.json` 或照片后页面没变**：dev server 会缓存 JSON 模块，
  重启一下即可

## 手动命令一览

正常流程用不到，需要时再跑：

```bash
npm run generate-gallery         # 重新生成照片清单
npm run compress-gallery         # 手动压缩（钩子已自动做）
npm run fetch-airline-icons      # 抓已拍到航司的图标
npm run fetch-airline-icons -- --all   # 抓表里全部航司
npm run build:check              # 验证生产构建（不影响 dev）
```

## 图标质量

图标抓的是航司官网 favicon，质量参差。脚本会把源图小于 32px 的列出来提醒。
想换更好的，从航司官方 media kit 下载后按代码命名放进
`public/static/images/airlines/`（如 `qr.png`），**已存在的文件脚本不会覆盖**。

细节见 `public/static/images/airlines/README.md`。
